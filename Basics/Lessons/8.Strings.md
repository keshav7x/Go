# Go Strings — From First Principles to Production

<p><b>Goal:</b> Don't just learn how to write `"hello"`. Understand what a Go string actually is, how it is stored, why <code>len()</code> can surprise you, why indexing gives bytes, how UTF-8 works, and when to use the standard string tools.</p>

---

# 1. What Is a String?

The simplest definition:

<p><b>A string in Go is an immutable sequence of bytes.</b></p>

That sentence is extremely important.

For example:

```go
name := "Keshav"
```

Conceptually, the string contains bytes representing:

```text
K e s h a v
```

For ordinary English characters, each character happens to use one byte in UTF-8.

So:

```text
"Keshav"

K → 1 byte
e → 1 byte
s → 1 byte
h → 1 byte
a → 1 byte
v → 1 byte
```

Total:

```text
6 bytes
```

Therefore:

```go
len("Keshav")
```

returns:

```text
6
```


As a backend engineer, you'll work with strings constantly.

# 4. Empty String

An empty string is:

```go
text := ""
```

Its length is:

```go
len(text)
```

which gives:

```text
0
```

Visual:

```text
""

┌───────────────┐
│   no bytes    │
└───────────────┘

len = 0
```

# 5. String Is Not an Array of Characters

This is a very important distinction.

You might imagine:

```text
string
   ↓
['H']['e']['l']['l']['o']
```

But Go doesn't fundamentally model strings as:

```text
array of characters
```

Instead:

```text
string
   ↓
sequence of bytes
```

For:

```go
"Hello"
```

the bytes are:

```text
72 101 108 108 111
```

because those are the UTF-8/ASCII byte values for those characters.

# 6. String Internals

For learning purposes, think of a Go string as roughly:

```text
┌──────────────────────┐
│ pointer to data      │
│ length in bytes      │
└──────────────────────┘
```

Conceptually:

```text
string
┌────────────────────┐
│ data ──────────────┼──────────┐
│ length = 5         │          │
└────────────────────┘          ↓
                         underlying bytes

                         ┌────┬────┬────┬────┬────┐
                         │ H  │ e  │ l  │ l  │ o  │
                         └────┴────┴────┴────┴────┘
```

The important part:

<p><b>A string stores bytes and knows how many bytes it contains.</b></p>

---

# 7. Strings Are Immutable

This is one of the biggest rules.

Suppose:

```go
name := "Keshav"
```

You cannot do:

```go
name[0] = 'A'
```

This is invalid.

Why?

Because Go strings are immutable.

Once a string value exists, you cannot directly modify its individual bytes.

---

# 8. Then How Do You Change a String?

You create another string.

For example:

```go
name := "Keshav"

name = "Rahul"
```

You're not modifying the old string.

You're assigning a different string value to the variable.

Think:

```text
Before:

name
 ↓
"Keshav"


After:

name
 ↓
"Rahul"
```

---

# 9. Why Are Strings Immutable?

Immutability makes strings safer and simpler to reason about.

Imagine multiple parts of a program referring to the same string data.

If strings could freely mutate:

```text
A ─────┐
       ↓
     "hello"
       ↑
B ─────┘
```

and A changed the data, B could unexpectedly observe the change.

With immutable strings:

```text
"hello"
```

stays `"hello"`.

If you need different content, you create a different string value.

# 10. String Indexing

You can access individual bytes using an index.

```go
text := "Hello"

fmt.Println(text[0])
```

But here's the important part:

It does **not** print:

```text
H
```

It prints the byte value:

```text
72
```

Because:

```go
text[0]
```

gives you a:

```text
byte
```

not a string character.

---

# 11. Why Does `text[0]` Return a Byte?

Because strings are byte sequences.

For:

```text
"Hello"
```

conceptually:

```text
index

0     1     2     3     4
↓     ↓     ↓     ↓     ↓
┌────┬────┬────┬────┬────┐
│ H  │ e  │ l  │ l  │ o  │
└────┴────┴────┴────┴────┘
```

Each position contains one byte.

So:

```go
text[0]
```

means:

```text
give me byte 0
```

---

# 12. Printing a Character

If you want to print it as a character:

```go
text := "Hello"

fmt.Printf("%c\n", text[0])
```

Output:

```text
H
```

Because `%c` tells `fmt` to format the numeric byte as a character.

---

# 13. String Indexing Is Byte Indexing

This sentence should be burned into your brain:

<p><b>String indexes in Go refer to bytes, not Unicode characters.</b></p>

For ASCII text, this looks normal because:

```text
1 character = 1 byte
```

But Unicode changes everything.

---

# 14. ASCII vs Unicode

English:

```text
A
B
C
```

typically uses one byte per character in UTF-8.

But characters such as:

```text
अ
न
क
中
🚀
❤️
```

can require multiple bytes.

So:

```text
character count ≠ byte count
```

This is one of the most important string concepts in Go.

---

# 15. UTF-8

Go source code uses UTF-8, and strings commonly contain UTF-8 encoded text.

UTF-8 is a way of representing Unicode characters as bytes.

Some characters need:

```text
1 byte
```

Some:

```text
2 bytes
```

Some:

```text
3 bytes
```

Some:

```text
4 bytes
```

For example:

```text
English character → often 1 byte
Many Indian-script characters → often 3 bytes
Emoji → often 4 bytes
```

The exact byte representation depends on the character.

# 16. The `len()` Trap

Consider:

```go
text := "hello"

fmt.Println(len(text))
```

Output:

```text
5
```

Easy.

Now:

```go
text := "नमस्ते"

fmt.Println(len(text))
```

You may expect:

```text
6
```

because visually there are several characters.

But `len()` doesn't count characters.

It counts:

<p><b>bytes.</b></p>

---

# 17. What Does `len(string)` Actually Mean?

For a string:

```go
len(text)
```

means:

```text
number of bytes in the string
```

Not:

```text
number of visible characters
```

Not:

```text
number of Unicode code points
```

Not:

```text
number of grapheme clusters
```

It is the byte length.

---

# 18. Why Does Go Do This?

Because Go treats strings as byte sequences.

This is extremely useful for systems programming and network/backend work.

For example:

```text
HTTP data
File data
Encoded data
Network protocols
Binary-ish content
UTF-8 text
```

all ultimately involve bytes.

Go doesn't hide that fundamental representation.

---

# 19. ASCII Example

For:

```go
text := "Go"
```

UTF-8 bytes are:

```text
G → 71
o → 111
```

So:

```go
len(text)
```

returns:

```text
2
```

And:

```go
text[0]
```

returns:

```text
71
```

---

# 20. Unicode Example

Consider:

```go
text := "é"
```

The character `é` is represented by multiple UTF-8 bytes.

Therefore:

```go
len(text)
```

can be:

```text
2
```

even though visually:

```text
é
```

looks like one character.

This is exactly why you must distinguish:

```text
bytes
vs
characters
```

---

# 21. Runes

When you want to work with Unicode code points, Go provides the concept of a:

```text
rune
```

A rune is an alias for:

```go
int32
```

You don't need to memorize the implementation detail right now.

The important mental model is:

```text
byte
  ↓
one raw byte

rune
  ↓
one Unicode code point
```

---

# 22. Byte vs Rune

Think:

```text
STRING
"नमस्ते"

        ↓

     UTF-8 bytes

[byte][byte][byte][byte]...
```

But when decoded:

```text
runes

[न][म][स्][त][े]
```

The number of bytes and number of runes can be different.

---

# 23. `range` Over a String

This is where `range` becomes extremely useful.

```go
text := "Hello"

for index, r := range text {
    fmt.Println(index, r)
}
```

The `r` is a rune.

For ASCII:

```text
index   rune

0       H
1       e
2       l
3       l
4       o
```

---

# 24. `range` Does UTF-8 Decoding

This is an important internal idea.

When you do:

```go
for index, r := range text
```

Go isn't simply saying:

```text
give me every byte
```

It walks through the UTF-8 encoded string and decodes Unicode code points.

Conceptually:

```text
UTF-8 bytes
     ↓
decode
     ↓
rune
     ↓
next UTF-8 sequence
     ↓
next rune
```

This is why `range` is useful for Unicode text.

---

# 25. `range` Index Is Still a Byte Index

This is subtle.

Suppose:

```go
text := "éa"
```

The first character may occupy multiple bytes.

When you do:

```go
for i, r := range text {
    fmt.Println(i, r)
}
```

the index represents the **byte position** where that rune begins.

It does not necessarily increase by one.

Conceptually:

```text
bytes

0    1    2
┌────┬────┬────┐
│ é  │ é  │ a  │
└────┴────┴────┘
 ↑              ↑
rune starts     rune starts
at 0            at 2
```

So the indexes might be:

```text
0 → é
2 → a
```

not:

```text
0 → é
1 → a
```

This is a very important Go detail.

---

# 26. `range` Without Index

If you only need the characters:

```go
text := "Hello"

for _, r := range text {
    fmt.Printf("%c\n", r)
}
```

Output:

```text
H
e
l
l
o
```

This is the standard way to iterate through Unicode code points.

---

# 27. Don't Use `text[i]` When You Mean "Character"

This:

```go
for i := 0; i < len(text); i++ {
    fmt.Printf("%c\n", text[i])
}
```

works for ASCII.

But it can break Unicode text because you're iterating byte-by-byte.

For example:

```text
"नमस्ते"
```

contains multi-byte UTF-8 sequences.

So byte-by-byte iteration can produce individual UTF-8 bytes rather than complete Unicode characters.

---

# 28. Use `range` for Unicode Characters

If your intention is:

```text
"Give me each Unicode code point."
```

use:

```go
for _, r := range text {
    fmt.Printf("%c\n", r)
}
```

This is one of the most important practical string rules.

---

# 29. Converting String to `[]byte`

You can convert a string into a byte slice:

```go
text := "Hello"

bytes := []byte(text)
```

Now:

```text
text
"Hello"

        ↓ conversion

bytes
[72 101 108 108 111]
```

The result is mutable because a byte slice is mutable.

---

# 30. Why Convert to `[]byte`?

Because strings are immutable.

Suppose you want to modify the bytes.

You cannot:

```go
text[0] = 'J'
```

Instead:

```go
bytes := []byte(text)

bytes[0] = 'J'

text = string(bytes)
```

Now:

```text
"Jello"
```

Mental model:

```text
string
  ↓
[]byte
  ↓
modify
  ↓
string
```

---

# 31. String → Rune Slice

If you want to work with Unicode code points:

```go
text := "नमस्ते"

runes := []rune(text)
```

Now you have a slice of runes.

Conceptually:

```text
string
"नमस्ते"

      ↓

[]rune

[न][म][स्][त][े]
```

Then you can work with the Unicode code points as elements.

---

# 32. Rune Slice vs Byte Slice

Remember:

```text
[]byte
```

means:

```text
raw bytes
```

while:

```text
[]rune
```

means:

```text
Unicode code points
```

Choose based on what you're actually trying to manipulate.

---

# 33. Converting Back

From bytes:

```go
bytes := []byte("Hello")

text := string(bytes)
```

From runes:

```go
runes := []rune("Hello")

text := string(runes)
```

Both can produce a string.

# 34. String Concatenation

The simplest way to join strings:

```go
first := "Hello"
second := "World"

result := first + " " + second
```

Result:

```text
Hello World
```

---

# 35. String Concatenation Is Creating New Strings

Remember:

```text
strings are immutable
```

So:

```go
result := first + second
```

doesn't mutate either original string.

Conceptually:

```text
first
"Hello"

second
"World"

       ↓ +

new string

"HelloWorld"
```

---

# 36. Repeated Concatenation

Suppose:

```go
result := ""

for i := 0; i < 1000; i++ {
    result += "hello"
}
```

This can cause repeated string allocations/copying.

Conceptually:

```text
""
 ↓
"hello"
 ↓
"hellohello"
 ↓
"hellohellohello"
 ↓
...
```

Every time the string grows, new data may need to be constructed.

For small strings, this is often completely fine.

For large repeated construction, use an appropriate builder.

---

# 37. `strings.Builder`

Go provides:

```go
strings.Builder
```

for efficiently constructing strings.

Example:

```go
var builder strings.Builder

builder.WriteString("Hello")
builder.WriteString(" ")
builder.WriteString("World")

result := builder.String()

fmt.Println(result)
```

Output:

```text
Hello World
```

---

# 38. Why `strings.Builder` Exists

Instead of repeatedly doing:

```text
old string
    +
new string
    ↓
new allocation
```

a builder provides a buffer-like place to construct the final string.

Conceptually:

```text
Builder

┌────────────────────────────┐
│ Hello World                │
└────────────────────────────┘
```

Then:

```go
builder.String()
```

produces the final string.

Use it when you're building strings incrementally, especially in loops.

# 53. String Comparison

Strings can be compared.

```go
a := "hello"
b := "hello"

fmt.Println(a == b)
```

Output:

```text
true
```

You can also use:

```go
a != b
a < b
a > b
a <= b
a >= b
```

String ordering is based on byte/lexicographic ordering.

---

# 54. Don't Confuse `==` With Case-Insensitive Equality

This:

```go
"Hello" == "hello"
```

is:

```text
false
```

If your application needs case-insensitive comparison, normalize appropriately or use a suitable string comparison approach.

For simple ASCII cases:

```go
strings.EqualFold(a, b)
```

can be useful for Unicode-aware case-insensitive comparison.

# 58. String Length vs Character Count

This deserves its own rule.

Suppose:

```go
text := "Hello"
```

Then:

```text
bytes   = 5
runes   = 5
```

Because ASCII characters are one byte each.

But with Unicode:

```text
text = "🚀"
```

you can have:

```text
bytes ≠ runes
```

So:

```go
len(text)
```

is not a universal "character count."

# 59. Counting Unicode Code Points

If you really want the number of Unicode code points:

```go
count := utf8.RuneCountInString(text)
```

using:

```go
import "unicode/utf8"
```

Or:

```go
count := len([]rune(text))
```


# 60. Three Different Questions

This is senior-level thinking even though the syntax is simple.

When someone asks:

> "How long is this string?"

You should ask:

```text
Do you mean:

1. Number of bytes?

2. Number of Unicode code points?

3. Number of user-perceived characters?
```

These are not necessarily the same.

---

# 61. User-Perceived Characters Are More Complicated

Even a rune is not always equivalent to what a human sees as one character.

For example, some visible characters can be constructed from multiple Unicode code points.

So:

```text
bytes
≠
runes
≠
user-perceived characters
```

For basic Go learning:

```text
byte → raw storage unit
rune → Unicode code point
```

is the important distinction.

# 62. `byte`

In Go:

```go
byte
```

is an alias for:

```go
uint8
```

Think:

```text
byte = 8 bits
```

String indexing gives you bytes.

Example:

```go
text := "Hello"

var b byte = text[0]
```

`b` contains the byte representing `H`.

---

# 63. `rune`

In Go:

```go
rune
```

is an alias for:

```go
int32
```

It is used to represent a Unicode code point.

Example:

```go
var r rune = 'A'
```

Notice:

```text
'A'
```

uses **single quotes**.

---

# 64. String vs Rune Literal

String:

```go
"hello"
```

Rune:

```go
'h'
```

Think:

```text
"hello"
   ↓
string

'h'
   ↓
rune
```

This distinction is important.

---

# 65. Single Quotes vs Double Quotes

```go
'A'
```

is a rune literal.

```go
"A"
```

is a string literal.

So:

```go
var r rune = 'A'
```

is valid.

And:

```go
var s string = "A"
```

is valid.

But they represent different types.

# 66. Converting a Rune to a String

Suppose:


You can do:

```go
text := string(r)
```

Result:

```text

```

This is useful when building strings from Unicode characters.

# 67. String Iteration: Byte vs Rune

Compare:

### Byte iteration

```go
text := "Hello"

for i := 0; i < len(text); i++ {
    fmt.Println(text[i])
}
```

This processes:

```text
bytes
```

### Rune iteration

```go
for _, r := range text {
    fmt.Println(r)
}
```

This processes:

```text
Unicode code points
```

Know which one your problem requires.

# 68. Converting to Bytes Can Be Useful for Protocol Work

Suppose you're dealing with:

```text
network data
binary formats
byte-oriented APIs
file content
hashing
encoding
```

You often care about the actual bytes:

```go
data := []byte(text)
```

In those situations, thinking in terms of characters may be the wrong abstraction.

Think:

```text
string → bytes → processing
```

---

# 69. Converting to Runes Can Be Useful for Text Processing

If you're doing something like:

```text
iterate Unicode characters
modify code points
reverse Unicode code points
inspect Unicode characters
```

you may use:

```go
runes := []rune(text)
```

Then:

```go
for i := range runes {
    fmt.Printf("%c\n", runes[i])
}
```

---

# 70. Reversing a String — Don't Naively Reverse Bytes

This is dangerous:

```go
bytes := []byte(text)

for i := 0; i < len(bytes)/2; i++ {
    j := len(bytes) - 1 - i

    bytes[i], bytes[j] = bytes[j], bytes[i]
}
```

For ASCII:

```text
"hello"
```

this works.

But for UTF-8:

```text
"नमस्ते"
```

reversing raw bytes can destroy the encoding.

If you're learning Unicode-aware string manipulation, work with runes instead.

---

# 71. Unicode-Aware Reverse

Conceptually:

```go
runes := []rune(text)

for i := 0; i < len(runes)/2; i++ {
    j := len(runes) - 1 - i

    runes[i], runes[j] = runes[j], runes[i]
}

result := string(runes)
```

This reverses Unicode code points rather than raw UTF-8 bytes.

But remember:

```text
rune ≠ always one user-perceived character
```

So even this isn't a perfect "reverse what a human sees as characters" algorithm for every possible Unicode string.

# 72. Strings and Memory

A useful mental model:

```text
string variable
┌─────────────────────┐
│ pointer             │
│ length              │
└──────────┬──────────┘
           │
           ↓
      immutable bytes

      ┌────┬────┬────┬────┐

      └────┴────┴────┴────┘
```

The exact runtime representation is an implementation detail, but this is the right conceptual model.

# 73. Why String Indexing Is Fast

When you do:

```go
text[i]
```

you're directly accessing the byte at position `i`.

Conceptually:

```text
string
 ↓
bytes
 ↓
index i
 ↓
byte
```

That's why byte indexing is straightforward and efficient.

But finding the Nth Unicode code point is different because UTF-8 characters can have different byte lengths.

---

# 74. Why Rune Iteration Is Different

Suppose:

```text
UTF-8 bytes:

[byte][byte][byte][byte][byte]...
```

A UTF-8 decoder must determine:

```text
Where does this code point end?

Where does the next one begin?
```

That's why:

```go
range
```

walks through the encoded bytes and decodes Unicode code points.

# 75. Strings Can Be Sliced

Just like slices, strings support slicing.

```go
text := "Hello"

part := text[1:4]
```

Result:

```text
"ell"
```

Because:

```text
H e l l o
0 1 2 3 4
  ↑     ↑
  1     4
```

Remember:

```text
start included
end excluded
```

---

# 76. String Slicing Is Byte-Based

This is VERY important.

String slicing:

```go
text[start:end]
```

uses byte indexes.

So with ASCII:

```text
easy
```

because:

```text
character = byte
```

With UTF-8:

```text
be careful
```

because you could cut through the middle of a multi-byte UTF-8 sequence.

---

# 77. Don't Arbitrarily Slice Unicode Strings by Byte Index

For example, don't assume:

```go
text[:5]
```

means:

```text
first 5 characters
```

It means:

```text
first 5 bytes
```

Those are different concepts.

If you need the first N Unicode code points, convert to runes or use appropriate UTF-8-aware logic.

# 78. String Equality

Strings can be directly compared:

```go
a := "hello"
```

Output:

# 79. Empty String Check

Very common:

```go
if text == "" {
    fmt.Println("empty")
}
```

This is clear and idiomatic.

You can also use:

```go
len(text) == 0
```

Both communicate emptiness.

For simple code, `text == ""` is often very readable.

# 80. Don't Use `strings.TrimSpace()` Automatically

Suppose you're validating a value:

```go
username := input
```

You shouldn't blindly do:

```go
username = strings.TrimSpace(username)
```

unless your application actually wants whitespace removed.

Different fields have different semantics.

For example:

```text
username → maybe trim
password → probably don't silently trim
free-form message → probably preserve
```

String operations should match the meaning of the data.

# 83. Production Practice: Don't Build Huge Strings With `+` in Loops

For tiny operations:


```text

```

# 84. Production Practice: Don't Convert Everything to `[]rune`

You might see:

```go

```

and think:

```text

```

No.

Conversion creates another representation.

If you only need:

```text

suffix check
ASCII processing
byte-oriented operations
```

you may not need a rune slice at all.

Use the representation that matches the task.

# 85. Production Practice: Don't Treat `len()` as Character Count

This mistake can cause bugs.

Bad assumption:

```go

    ...
}
```

Question:

> Do you mean 20 bytes or 20 Unicode code points?

If the requirement is:

```text
maximum 20 bytes
```

then:

```go
len(username)
```

is appropriate.

If it's:

```text
maximum 20 Unicode code points
```

you need Unicode-aware counting.

Requirements determine implementation.

# 86. Production Practice: Be Careful With User Input

User input can contain:

```text
combining characters
```

Don't assume:

```text

```

That's one of the easiest ways to write broken text handling.

# 116. The String Rules You Should Memorize

```text
1. A Go string is an immutable sequence of bytes.

2. Strings commonly contain UTF-8 encoded text.

3. len(string) returns byte length.

4. string[i] returns a byte.

5. Strings cannot be modified in place.

6. "hello" is a string.

7. 'h' is a rune literal.

8. byte represents one byte.

9. rune represents a Unicode code point.

10. range over a string decodes UTF-8 and gives runes.

11. range's index is a byte index.

12. String slicing uses byte indexes.

13. []byte(string) gives mutable byte data.

14. []rune(string) gives Unicode code points.

15. string(bytes) converts bytes back to a string.

16. string(runes) converts runes back to a string.

17. Use strings package utilities instead of reinventing them.

18. Use strings.Builder for substantial repeated string construction.

19. Don't assume one character = one byte.

20. Always know whether you're working with bytes,
    Unicode code points, or user-perceived characters.
```
