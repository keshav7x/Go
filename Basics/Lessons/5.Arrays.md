
# Go Arrays — From First Principles

<p><b>Goal:</b> By the end of this lesson, you should not just know how to write an array in Go. You should understand what an array actually is, why it exists, how indexing works, how Go treats arrays, how arrays behave when copied, how to iterate over them, and the mistakes you need to avoid.</p>

<p><b>Important:</b> This lesson is about arrays only. No deep dive into slices, maps, structs, pointers, or other concepts.</p>

---

# 1. First Principles: What Problem Does an Array Solve?

Imagine you want to store five numbers.

Without an array:

```go
a := 10
b := 20
c := 30
d := 40
e := 50
```

This is fine for five values.

But imagine you need 100 values.

You would end up with:

```text
a1
a2
a3
a4
...
a100
```

That's obviously not a good way to represent related data.

What we really want is something like:

```text
numbers
    ↓

┌────┬────┬────┬────┬────┐
│ 10 │ 20 │ 30 │ 40 │ 50 │
└────┴────┴────┴────┴────┘
  0    1    2    3    4
```

One name.

Multiple values.

Each value has a position.

That's the fundamental idea of an array.

<p><b>An array is a fixed-size collection of elements of the same type.</b></p>

---

# 2. The Simplest Possible Definition

If you remember only one sentence from this entire lesson:

<p><b>Array = fixed number of values of the same type, stored in a sequence and accessed using indexes.</b></p>

For example:

```go
numbers := [5]int{10, 20, 30, 40, 50}
```

This tells Go:

```text
Name:
numbers

Number of elements:
5

Type of each element:
int

Indexes:
0, 1, 2, 3, 4
```

Visualize it:

```text
numbers

┌────┬────┬────┬────┬────┐
│ 10 │ 20 │ 30 │ 40 │ 50 │
└────┴────┴────┴────┴────┘
  ↑    ↑    ↑    ↑    ↑
  0    1    2    3    4
```

---

# 3. Why Is an Array Called "Fixed-Size"?

Look at this:

```go
numbers := [5]int{10, 20, 30, 40, 50}
```

The `5` means:

```text
"This array has exactly 5 elements."
```

Not 4.

Not 6.

Exactly 5.

```text
[5]int

┌────┬────┬────┬────┬────┐
│    │    │    │    │    │
└────┴────┴────┴────┴────┘
  0    1    2    3    4
```

Once the array has type:

```go
[5]int
```

its length is fixed.

This is one of the biggest characteristics of Go arrays.

---

# 4. Understanding `[5]int`

When you see:

```go
[5]int
```

don't look at it as random syntax.

Read it as:

```text
[5]int
 │ │
 │ └── type of every element
 │
 └──── number of elements
```

Therefore:

```go
[5]int
```

means:

<p><b>"An array containing exactly 5 integers."</b></p>

Similarly:

```go
[10]string
```

means:

<p><b>"An array containing exactly 10 strings."</b></p>

And:

```go
[3]float64
```

means:

<p><b>"An array containing exactly 3 float64 values."</b></p>

# 5. Declaration

The general syntax is:

```go
var name [size]type
```

Example:

```go
var numbers [5]int
```

Let's break it down:

```text
var numbers [5]int
│      │      │
│      │      └── element type
│      └───────── number of elements
└──────────────── declaration
```

After this:

```go
var numbers [5]int
```

you have an array with five integer positions.

```text
┌────┬────┬────┬────┬────┐
│  0 │  0 │  0 │  0 │  0 │
└────┴────┴────┴────┴────┘
  0    1    2    3    4
```

---

# 6. Go's Zero Value

Notice something important.

We wrote:

```go
var numbers [5]int
```

We didn't provide any values.

But Go still gives us:

```text
[0 0 0 0 0]
```

Why?

Because each `int` gets its zero value:

```text
int → 0
```

So:

```go
var numbers [5]int

fmt.Println(numbers)
```

prints:

```text
[0 0 0 0 0]
```

This is normal Go behavior.

You don't need to manually put zero into every position.

# 7. Initializing an Array

You can provide values while creating the array:

```go
numbers := [5]int{10, 20, 30, 40, 50}
```

Now:

```text
┌────┬────┬────┬────┬────┐
│ 10 │ 20 │ 30 │ 40 │ 50 │
└────┴────┴────┴────┴────┘
  0    1    2    3    4
```

The five values correspond to the five positions.

```text
index 0 → 10
index 1 → 20
index 2 → 30
index 3 → 40
index 4 → 50
```

---

# 8. Indexing — The Heart of Arrays

An array becomes useful because we can access individual elements.

The syntax is:

```go
array[index]
```

For example:

```go
numbers := [5]int{10, 20, 30, 40, 50}

fmt.Println(numbers[0])
```

Output:

```text
10
```

And:

```go
fmt.Println(numbers[3])
```

Output:

```text
40
```

Think of the index as the element's position:

```text
             INDEX

              0    1    2    3    4
              ↓    ↓    ↓    ↓    ↓

numbers →   10   20   30   40   50
```

So:

```go
numbers[2]
```

means:

<p><b>"Give me the value stored at position 2."</b></p>

---

# 9. Why Does Indexing Start From 0?

This is extremely important.

For five elements:

```text
┌────┬────┬────┬────┬────┐
│ 10 │ 20 │ 30 │ 40 │ 50 │
└────┴────┴────┴────┴────┘
  0    1    2    3    4
```

The first element is index `0`.

The second is index `1`.

The third is index `2`.

And so on.

You can think of the index as:

<p><b>"How many positions away from the beginning is this element?"</b></p>

The first element is zero positions away.

```text
Beginning
   ↓
┌────┬────┬────┬────┬────┐
│ 10 │ 20 │ 30 │ 40 │ 50 │
└────┴────┴────┴────┴────┘
  ↑
  0
```

---

# 10. The Last Index

This is one of the most important rules.

If an array has length `N`:

```text
last index = N - 1
```

For:

```go
numbers := [5]int{10, 20, 30, 40, 50}
```

the length is:

```text
5
```

Therefore:

```text
last index = 5 - 1
           = 4
```

So:

```go
numbers[4]
```

is valid.

But:

```go
numbers[5]
```

is not.

Visual:

```text
Length = 5

┌────┬────┬────┬────┬────┐
│ 10 │ 20 │ 30 │ 40 │ 50 │
└────┴────┴────┴────┴────┘
  0    1    2    3    4
                       ↑
                   last index
```

---

# 11. The Golden Rule of Array Indexes

Memorize this:

```text
For an array of length N:

First valid index = 0

Last valid index = N - 1

Valid index condition:

0 <= index < N
```

For example:

```text
N = 5

0 <= index < 5
```

Therefore:

```text
0 ✓
1 ✓
2 ✓
3 ✓
4 ✓
5 ✗
```

This one rule will save you from a huge number of bugs.

# 12. Accessing an Element

Example:

```go
numbers := [5]int{10, 20, 30, 40, 50}

first := numbers[0]
third := numbers[2]
last := numbers[4]

fmt.Println(first)
fmt.Println(third)
fmt.Println(last)
```

Output:

```text
10
30
50
```

Notice:

```text
first → index 0
third → index 2
last  → index 4
```

---

# 13. Modifying an Element

Arrays are mutable.

That means you can change an existing element.

```go
numbers := [5]int{10, 20, 30, 40, 50}

numbers[2] = 999
```

Before:

```text
[10 20 30 40 50]
        ↑
      index 2
```

After:

```text
[10 20 999 40 50]
```

The array itself remains the same array.

Only the value at index `2` changed.

# 14. Reading vs Writing

This distinction is simple but important.

### Reading

```go
value := numbers[2]
```

means:

```text
array
  ↓
index 2
  ↓
give me the value
```

### Writing

```go
numbers[2] = 999
```

means:

```text
array
  ↓
index 2
  ↓
replace its value
  ↓
999
```

Think:

```text
                numbers[2]

                    ↓

             ┌────┬────┬────┬────┐
             │ 10 │ 20 │ 30 │ 40 │
             └────┴────┴────┴────┘
                       ↑
                    index 2
```

# 15. Array Length With `len()`

Go provides:

```go
len(array)
```

to get the number of elements.

Example:

```go
numbers := [5]int{10, 20, 30, 40, 50}

fmt.Println(len(numbers))
```

Output:

```text
5
```

So:

```text
numbers
   ↓
[10 20 30 40 50]
   ↓
len(numbers)
   ↓
5
```

<p><b>`len()` tells you how many elements the array contains.</b></p>

---

# 16. Why `len()` Matters

You could write:

```go
for i := 0; i < 5; i++ {
    fmt.Println(numbers[i])
}
```

But this duplicates information.

You already know the array's length.

Instead:

```go
for i := 0; i < len(numbers); i++ {
    fmt.Println(numbers[i])
}
```

Now the loop gets the actual length from the array.

This is better because the code describes the relationship:

```text
index < array length
```

rather than:

```text
index < some random number I wrote earlier
```

# 17. Arrays + Loops

This is where your previous loops knowledge connects.

Suppose:

```go
numbers := [5]int{10, 20, 30, 40, 50}
```

We can process every element:

```go
for i := 0; i < len(numbers); i++ {
    fmt.Println(numbers[i])
}
```

Let's mentally execute it:

```text
i = 0
↓
numbers[0]
↓
10

i = 1
↓
numbers[1]
↓
20

i = 2
↓
numbers[2]
↓
30

i = 3
↓
numbers[3]
↓
40

i = 4
↓
numbers[4]
↓
50

i = 5
↓
5 < 5 → false
↓
STOP
```

This is the fundamental array + loop pattern.

# 18. The Off-by-One Problem

One of the most common array bugs:

```go
for i := 0; i <= len(numbers); i++ {
    fmt.Println(numbers[i])
}
```

Looks almost correct.

But it isn't.

Suppose:

```text
len(numbers) = 5
```

The loop allows:

```text
i = 0
i = 1
i = 2
i = 3
i = 4
i = 5
```

The problem is:

```text
i = 5
```

because:

```go
numbers[5]
```

doesn't exist.

Correct:

```go
for i := 0; i < len(numbers); i++ {
    fmt.Println(numbers[i])
}
```

Remember:

```text
❌ i <= len(numbers)

✅ i < len(numbers)
```

# 19. Array Size Is Part of the Type

This is a very important Go-specific concept.

Consider:

```go
a := [3]int{10, 20, 30}
b := [5]int{10, 20, 30, 40, 50}
```

Their types are:

```text
a → [3]int

b → [5]int
```

These are different types.

```text
[3]int ≠ [5]int
```

Why?

Because the number of elements is part of the type.

So when you see:

```go
[3]int
```

don't just think:

```text
"array of ints"
```

Think:

```text
"exactly 3 ints"
```

# 20. Different Element Types

Arrays can contain different basic types.

For example:

```go
numbers := [3]int{10, 20, 30}
```

```go
prices := [3]float64{10.5, 20.5, 30.5}
```

```go
names := [3]string{"Keshav", "Rahul", "Aman"}
```

But each individual array has one element type.

For:

```go
[3]int
```

all three elements are:

```text
int
```

For:

```go
[3]string
```

all three elements are:

```text
string
```

You don't mix unrelated types inside one normal array.

# 21. Partial Initialization

You can provide fewer values than the array's size.

Example:

```go
numbers := [5]int{10, 20}
```

Go fills the remaining positions with zero values.

Result:

```text
[10 20 0 0 0]
```

Visual:

```text
┌────┬────┬────┬────┬────┐
│ 10 │ 20 │  0 │  0 │  0 │
└────┴────┴────┴────┴────┘
  0    1    2    3    4
```

This works because the array still has exactly five elements.

# 22. Let Go Count the Size

There is another useful syntax:

```go
numbers := [...]int{10, 20, 30, 40, 50}
```

The `...` tells Go:

<p><b>"You count how many elements there are."</b></p>

Go sees:

```text
10
20
30
40
50
```

That's five values.

So the resulting type is effectively:

```text
[5]int
```

Conceptually:

```text
[...]int{10, 20, 30, 40, 50}
              ↓
          Go counts
              ↓
            [5]int
```

---

# 23. Explicit Size vs `...`

These:

```go
numbers := [5]int{10, 20, 30, 40, 50}
```

and:

```go
numbers := [...]int{10, 20, 30, 40, 50}
```

both produce an array with five elements.

The difference is simply:

```text
[5]int
   ↓
You specify the size.

[...]int
     ↓
Go determines the size.
```

Use whichever communicates the intent better.

# 24. Arrays Are Values

This is where Go becomes interesting.

Consider:

```go
a := [3]int{10, 20, 30}
b := a
```

What is `b`?

It is a copy of the array value.

Conceptually:

```text
a

┌────┬────┬────┐
│ 10 │ 20 │ 30 │
└────┴────┴────┘


b

┌────┬────┬────┐
│ 10 │ 20 │ 30 │
└────┴────┴────┘
```

Now:

```go
b[0] = 999
```

The result is:

```text
a → [10 20 30]

b → [999 20 30]
```

`a` didn't change.

---

# 25. Why Didn't `a` Change?

Because:

```go
b := a
```

copies the array value.

Think:

```text
             a
             │
             │ array value
             ↓
        ┌───────────┐
        │ 10 20 30  │
        └───────────┘
             │
             │ copy
             ↓
        ┌───────────┐
        │ 10 20 30  │
        └───────────┘
             │
             ↓
             b
```

Now modifying `b` modifies its array value.

```text
a → [10 20 30]

b → [999 20 30]
```

This is a very important property of Go arrays.

# 26. Arrays and Functions

Arrays can be passed to functions.

Example:

```go
func printNumbers(numbers [3]int) {
    for _, value := range numbers {
        fmt.Println(value)
    }
}
```

Then:

```go
numbers := [3]int{10, 20, 30}

printNumbers(numbers)
```

The function receives the array value.

Because arrays are values, the array is passed as a value.

Conceptually:

```text
main

[10 20 30]
     │
     │ copy
     ↓
function

[10 20 30]
```

---

# 27. Changing an Array Inside a Function

Consider:

```go
func change(numbers [3]int) {
    numbers[0] = 999
}

func main() {
    numbers := [3]int{10, 20, 30}

    change(numbers)

    fmt.Println(numbers)
}
```

Output:

```text
[10 20 30]
```

Why?

Because the function modified its own array value.

Conceptually:

```text
main:

[10 20 30]

       │
       │ copy
       ↓

function:

[10 20 30]

       │
       │ modify
       ↓

[999 20 30]
```

The original remains:

```text
[10 20 30]
```

<p><b>For now, just remember: arrays behave as values.</b></p>

# 28. Comparing Arrays

Arrays can be compared when their element type supports comparison.

Example:

```go
a := [3]int{10, 20, 30}
b := [3]int{10, 20, 30}

fmt.Println(a == b)
```

Output:

```text
true
```

Because corresponding elements are equal.

```text
a → [10 20 30]
b → [10 20 30]

10 == 10 ✓
20 == 20 ✓
30 == 30 ✓

        ↓

      true
```

If:

```go
a := [3]int{10, 20, 30}
b := [3]int{10, 20, 40}
```

then:

```go
fmt.Println(a == b)
```

produces:

```text
false
```

# 29. `range` With Arrays

Go gives you a clean way to iterate through an array:

```go
numbers := [5]int{10, 20, 30, 40, 50}

for index, value := range numbers {
    fmt.Println(index, value)
}
```

Output:

```text
0 10
1 20
2 30
3 40
4 50
```

Here:

```text
index → current position

value → current value
```

Visual:

```text
index:    0    1    2    3    4
          ↓    ↓    ↓    ↓    ↓

value:   10   20   30   40   50
```

---

# 30. When You Don't Need the Index

Sometimes you only care about the values.

Instead of:

```go
for i := 0; i < len(numbers); i++ {
    fmt.Println(numbers[i])
}
```

you can write:

```go
for _, value := range numbers {
    fmt.Println(value)
}
```

Here:

```text
_     → ignore the index

value → current element
```

So:

```text
for _, value := range numbers
     │      │
     │      └── value
     │
     └───────── index ignored
```

This is cleaner when you don't need the position.

---

# 31. When Should You Use Which Loop?

Simple rule:

```text
Need the index?
      ↓
Use an index-based loop
or range with index.

Need only the value?
      ↓
Use range with _.
```

Example:

```go
for i := 0; i < len(numbers); i++ {
    fmt.Println(i, numbers[i])
}
```

Use this when the index matters.

But:

```go
for _, value := range numbers {
    fmt.Println(value)
}
```

is cleaner when the index doesn't matter.

<p><b>Choose the loop based on intent, not habit.</b></p>

---

# 32. `range` and Modifying Elements

This is an important thing to understand.

Consider:

```go
numbers := [3]int{10, 20, 30}

for _, value := range numbers {
    value = value * 2
}

fmt.Println(numbers)
```

You might expect:

```text
[20 40 60]
```

But you get:

```text
[10 20 30]
```

Why?

Because you're changing the loop variable:

```text
array element
     ↓
   value
     ↓
modify value
```

You're not assigning the modified value back into the array.

If you want to modify actual array elements:

```go
numbers := [3]int{10, 20, 30}

for i := 0; i < len(numbers); i++ {
    numbers[i] = numbers[i] * 2
}
```

Now:

```text
[20 40 60]
```

The key idea:

```text
range value → current value

numbers[i] → actual array position
```

# 33. Array + `break`

You can stop processing the array using `break`.

```go
numbers := [5]int{10, 20, 30, 40, 50}

for _, value := range numbers {
    if value == 30 {
        break
    }

    fmt.Println(value)
}
```

Output:

```text
10
20
```

Execution:

```text
10 → print
20 → print
30 → break
40 → never reached
50 → never reached
```

---

# 34. Array + `continue`

You can skip an element using `continue`.

```go
numbers := [5]int{10, 20, 30, 40, 50}

for _, value := range numbers {
    if value == 30 {
        continue
    }

    fmt.Println(value)
}
```

Output:

```text
10
20
40
50
```

Execution:

```text
10 → print
20 → print
30 → skip
40 → print
50 → print
```

---

# 35. `break` vs `continue`

Remember:

```text
break
  ↓
STOP THE LOOP
```

while:

```text
continue
  ↓
SKIP CURRENT ITERATION
  ↓
GO TO NEXT ITERATION
```

Visual:

```text
                  LOOP
                    │
             ┌──────┴──────┐
             │             │
           break        continue
             │             │
             ↓             ↓
          STOP LOOP    skip current
                          │
                          ↓
                    next iteration
```

# 36. Reverse Through an Array

You can also iterate backwards.

```go
numbers := [5]int{10, 20, 30, 40, 50}

for i := len(numbers) - 1; i >= 0; i-- {
    fmt.Println(numbers[i])
}
```

Output:

```text
50
40
30
20
10
```

Why does it start at:

```go
len(numbers) - 1
```

?

Because that's the last valid index.

For length 5:

```text
len(numbers) - 1
       ↓
       5 - 1
       ↓
       4
```

Then:

```text
4
3
2
1
0
```

---

# 37. Reverse Loop Boundary

This is wrong:

```go
for i := len(numbers); i >= 0; i-- {
    fmt.Println(numbers[i])
}
```

Why?

Because:

```text
len(numbers) = 5
```

but:

```text
last valid index = 4
```

So the first access becomes:

```go
numbers[5]
```

which is invalid.

Correct:

```go
for i := len(numbers) - 1; i >= 0; i-- {
    fmt.Println(numbers[i])
}
```

# 38. Nested Loops and Arrays

Arrays can also be used with nested loops.

For example:

```go
numbers := [3]int{10, 20, 30}

for i := 0; i < len(numbers); i++ {
    for j := 0; j < 2; j++ {
        fmt.Println(numbers[i], j)
    }
}
```

The important thing to understand is simply:

```text
Outer loop
    ↓
choose array position
    ↓
inner loop runs completely
    ↓
outer loop moves to next position
```

Visual:

```text
i = 0
 └── j = 0
 └── j = 1

i = 1
 └── j = 0
 └── j = 1

i = 2
 └── j = 0
 └── j = 1
```

Nested loops are useful when the problem naturally requires one loop inside another.

Don't use them just because you can.

# 39. Arrays and Memory — Basic Internal Model

Now let's understand what an array looks like conceptually in memory.

Suppose:

```go
numbers := [4]int{10, 20, 30, 40}
```

Conceptually:

```text
Memory

┌────────┬────────┬────────┬────────┐
│   10   │   20   │   30   │   40   │
└────────┴────────┴────────┴────────┘
    0        1        2        3
```

The elements have the same type.

That means their representation has a consistent size.

Conceptually, accessing an index can be thought of as:

```text
element location
      =
array beginning
      +
(index × element size)
```

For example:

```text
numbers[3]

        ↓

array beginning
        +
3 × element size
        ↓
element at index 3
```

You don't need to implement this yourself.

The important idea is:

<p><b>Arrays have a predictable layout, and an index identifies a specific position.</b></p>

---

# 40. Why Array Access Is Direct

Suppose:

```go
numbers := [5]int{10, 20, 30, 40, 50}
```

You want:

```go
numbers[4]
```

Go knows that you want:

```text
index 4
```

It doesn't need to search for the value `50`.

The index identifies the position directly.

```text
┌────┬────┬────┬────┬────┐
│ 10 │ 20 │ 30 │ 40 │ 50 │
└────┴────┴────┴────┴────┘
  0    1    2    3    4
                   ↑
                   │
                direct
                position
```

This predictable layout is one of the fundamental characteristics of arrays.

# 41. Array Assignment

Consider:

```go
a := [3]int{10, 20, 30}
b := a
```

This is valid because both are:

```text
[3]int
```

Now:

```go
b[1] = 999
```

The result:

```text
a → [10 20 30]

b → [10 999 30]
```

The arrays are independent values.

# 42. Different Array Sizes

This:

```go
[3]int
```

is different from:

```go
[4]int
```

and:

```go
[5]int
```

Think of them as completely different array types:

```text
[3]int
┌────┬────┬────┐
│    │    │    │
└────┴────┴────┘


[4]int
┌────┬────┬────┬────┐
│    │    │    │    │
└────┴────┴────┴────┘


[5]int
┌────┬────┬────┬────┬────┐
│    │    │    │    │    │
└────┴────┴────┴────┴────┘
```

The length is part of the type.

That's why:

```text
[3]int ≠ [4]int
```

# 43. When Are Arrays Actually Useful?

The important question isn't:

<p>"Can I use an array?"</p>

It's:

<p><b>"Does this data naturally have a fixed number of elements?"</b></p>

Examples:

```text
7 days of the week

12 months

3 fixed coordinates

4 fixed values

a fixed-size set of values
```

For example:

```go
days := [7]string{
    "Monday",
    "Tuesday",
    "Wednesday",
    "Thursday",
    "Friday",
    "Saturday",
    "Sunday",
}
```

The number seven has meaning.

That's a natural fit for an array.

# 44. Production-Grade Array Practices

## 44.1 Know the Boundary

Whenever you write:

```go
numbers[index]
```

you should know:

```text
0 <= index < len(numbers)
```

Don't randomly assume an index is valid.

---

## 44.2 Prefer `len()` Over Magic Numbers

Instead of:

```go
for i := 0; i < 5; i++ {
```

prefer:

```go
for i := 0; i < len(numbers); i++ {
```

This makes your loop directly depend on the array.

---

## 44.3 Don't Use `<=` for Normal Index Iteration

Usually:

```go
i < len(numbers)
```

is correct.

Not:

```go
i <= len(numbers)
```

Because:

```text
len(numbers)
```

is the number of elements, not the last index.

---

## 44.4 Don't Modify the Loop Variable for No Reason

Avoid confusing code like:

```go
for i := 0; i < len(numbers); i++ {
    i++
}
```

Now the loop's movement is happening in multiple places.

Keep the loop's control predictable.

---

## 44.5 Use `range` When It Communicates Intent

If you simply want every value:

```go
for _, value := range numbers {
    fmt.Println(value)
}
```

This tells the reader:

<p>"I care about the values, not their positions."</p>

---

## 44.6 Use an Index When Position Matters

If your logic actually needs:

```text
0
1
2
3
...
```

then make that obvious:

```go
for i := 0; i < len(numbers); i++ {
    fmt.Println(i, numbers[i])
}
```

Don't hide index-based logic.

---

## 44.7 Don't Make Array Code Clever

Bad code isn't necessarily code that doesn't work.

Sometimes code works but is unnecessarily difficult to understand.

Prefer:

```go
for i := 0; i < len(numbers); i++ {
    fmt.Println(numbers[i])
}
```

over some clever one-liner that makes the reader decode what is happening.

<p><b>Readable code wins.</b></p>

# 45. Common Mistakes

## Mistake 1 — Thinking the First Index Is 1

Wrong:

```text
1 2 3 4 5
```

Correct:

```text
0 1 2 3 4
```

for an array of length five.

---

## Mistake 2 — Accessing `numbers[len(numbers)]`

Suppose:

```go
numbers := [5]int{}
```

Then:

```text
len(numbers) = 5
```

But:

```go
numbers[5]
```

is invalid.

The last valid index is:

```text
len(numbers) - 1
```

which is:

```text
4
```

---

## Mistake 3 — Using `<=`

Wrong:

```go
for i := 0; i <= len(numbers); i++ {
```

Correct:

```go
for i := 0; i < len(numbers); i++ {
```

---

## Mistake 4 — Forgetting the Size Is Part of the Type

Don't think:

```text
[3]int
```

and:

```text
[5]int
```

are the same type.

They aren't.

---

## Mistake 5 — Forgetting Arrays Are Values

Don't expect:

```go
b := a
```

to make changes to `b` automatically change `a`.

The array value is copied.

---

## Mistake 6 — Changing a `range` Value

This:

```go
for _, value := range numbers {
    value = 100
}
```

doesn't change the actual array elements.

If you need to modify positions, use the index.

# 46. A Complete Small Example

Let's combine the fundamentals.

```go
package main

import "fmt"

func main() {
    numbers := [5]int{10, 20, 30, 40, 50}

    fmt.Println("Length:", len(numbers))

    fmt.Println("First:", numbers[0])

    numbers[2] = 999

    fmt.Println("After modification:", numbers)

    for i := 0; i < len(numbers); i++ {
        fmt.Println("Index:", i, "Value:", numbers[i])
    }
}
```

The important parts:

```text
Create array
    ↓
Access element
    ↓
Modify element
    ↓
Get length
    ↓
Loop through elements
```

You should be able to explain every line without memorizing it.

# 54. Final Rules

<p><b>Rule 1:</b> An array has a fixed number of elements.</p>

<p><b>Rule 2:</b> Every element has the same type.</p>

<p><b>Rule 3:</b> Indexing starts at zero.</p>

<p><b>Rule 4:</b> The last valid index is <code>len(array) - 1</code>.</p>

<p><b>Rule 5:</b> A valid index satisfies:</p>

```text
0 <= index < len(array)
```

<p><b>Rule 6:</b> The array length is part of its type.</p>

<p><b>Rule 7:</b> Arrays are values, so assigning an array copies its value.</p>

<p><b>Rule 8:</b> Use <code>len()</code> instead of unnecessary hardcoded lengths.</p>

<p><b>Rule 9:</b> Use an index when the position matters.</p>

<p><b>Rule 10:</b> Use <code>range</code> when you simply want to iterate through the values.</p>

<p><b>Rule 11:</b> Be extremely careful about array boundaries.</p>

<p><b>Rule 12:</b> Keep array and loop code boring, obvious, and easy to verify.</p>
